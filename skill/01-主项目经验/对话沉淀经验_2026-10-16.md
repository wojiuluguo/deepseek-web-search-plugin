# 主项目对话沉淀经验（2026-09-28 ~ 2026-10-16）

> 来源：主项目 v1.25.0 搜索压测轮、v1.25.1 外部审计裁决轮、v1.25.2 子服务同步裁决轮、文档重构轮的开发对话。
> 与《代码问题清单_v1.24.0》衔接（那份记录到 v1.24.x 为止），本文件是之后的增量。只增不删。

## A. bug 裁决纪律

1. **四步法定性**：判定 → 理由 → 反问 → 确认；**100% 确认才修**，否则搁置并记录"不确定原因 + 观察计划"。外部审计 8 条质疑走了全程：4 修 4 搁置，无一凭感觉。
2. **非 bug 也要实验定性**：GBK stderr 二次崩溃嫌疑用实验驳回（Python 3.14 stderr 实测 UTF-8 输出 + backslashreplace 语义，中文正常写出不抛异常）——不是"看着像就不是"，是"做了实验才说不是"。
3. **死代码指控先查活调用方**：审计称 `check_local_index` 是死代码，grep 发现 cross_search 有活调用 → 指驳回；同轮 `verify_capture._md5_file` 确认零调用方 → 确删。两条同一流程、两种结论。
4. **同步清单裁决先做指示判定**：逐项区分"明确指名主项目待同步 / 验收附属 / 不适用 / 备忘"，只有第一类才进修复流程；对方的台账文档不代改，裁决写自己文档。

## B. 安全修复模式

5. **破坏性操作必须有目录边界护栏**：`--clean/--assemble` 这类删除操作要求目标在本项目 `downloads/` 树内（`_within_downloads`），越界 exit 2 明确拒绝——junk 判定含"图片<150KB"，指到相册就是不可逆误删。
6. **入口白名单要双层设防**：`_require_http_url` 同时挡 urllib 层与 Playwright 兜底层——crawl 的 `except` 会吞掉第一层拒绝转浏览器重试，`goto file://` 照样读本地文件。**只有一层 = 没防住**（测试已证）。
7. **净化放聚合源头，不放逐出口**：隐形字符剥离接线在 dispatch/browser 返回前 + own_search 入库前，下游 5 份 `_format_plain` 与 JSON 自动干净——逐出口接线是副本漂移温床（对照：子服务无 server 场景在出口净化，架构不同选择不同，理由讲清楚）。
8. **envelope 的 ok 必须绑定 returncode**：`or "{}"` 兜底会把"失败 + 空 stdout"兜成成功下发，消费方 KeyError。同理警惕一切"空值兜成默认值"掩盖失败的模式。
9. **私网护栏防绕过**：`lan --hosts` 显式主机必须逐一过 RFC1918 校验（实测拒 8.8.8.8）——参数级护栏要在参数解析处生效，不能只挡默认路径。

## C. 测试经验

10. **测试内直接 patch 优于命令行注入**：测 runner envelope 用测试进程内替换 `R.subprocess.run`（FakeProc），不要用 `python -c` 传 monkeypatch 代码——PowerShell/Windows 命令行转义会截断，stdout 空报 IndexError。
11. **测试文件禁止 `sys.path.insert(0, searchkit/)`**：searchkit/http.py 会遮蔽 stdlib http → `ModuleNotFoundError: http.client`。需要 scripts 入 path 时插入的是 scripts 目录且只用于 import 门面。
12. **验收用例要固化进回归**：对方指定的 ASCII 保留用例（`sanitize_output('abc123 XYZ 中文 456 https://a.com/x?y=1 2026年')` 原样）直接写成测试——同步修复的验收标准由提出方定义、落进自己的回归套件。
13. **夹具先行**：真实录制的引擎 HTML 存 tests/fixtures/engine_html/，站点改版后跑一次即知哪个选择器该修（v1.24.0 清单 #4 的落地）。

## D. 环境 / Windows

14. **PowerShell 不支持 heredoc**：长 commit message 写临时文件后 `git commit -F`；`python -c` 内联多行代码转义易炸 → 写临时脚本文件执行（放 %TEMP%，用完删，项目目录不留调试残渣）。
15. **文档文件换行符**：批量重构 .md 用 Python 读写并保 `newline=''`（本项目文档是 CRLF）；PowerShell Set-Content 会统一改写换行符。
16. **git push 分支名**：`git push origin HEAD` 而不是猜 master/main（本仓库实际是 main）。

## E. 文档 / 发版

17. **双语文档必须对称**：英文是默认视图，详细内容不能只有中文（CHANGELOG 初版只中文 = 把英文用户当二等公民，已纠正为 CHANGELOG.md 英文 + CHANGELOG.zh-CN.md 中文，28 版逐一对齐）。
18. **更新记录独立成 CHANGELOG**：版本时间轴（树状图 + 逐版速览）+ 分月索引 + 详细记录三层；README 只留最近 3 版摘要 + 链接（516 行 → 247 行）。
19. **发版红线要机制化**：`search-api-service/` 不入库不进 zip——.gitignore 挡一层 + 发版前 `git ls-files search-api-service` 复核必须为 0 条。**只写进文档不落实机制不算防住**。
20. **git archive 打包天然继承 .gitignore**：比手工挑文件可靠；打包前 `git ls-files` 审一遍清单。
21. **累积发版**：修复/测试 ≠ 发版；用户明确说"更新/发版/同步"才执行统一发版；Release Notes 双语（英文前中文后）、每版重写、有用的内容放前面。
22. **版本号四处同步**：SKILL.md、package.json、双语 README 头部、CHANGELOG 新条目（v1.12.1 时代问题 7 的教训沿用至今）。
