# 开发 Skill：改动回溯排查法 与 防坑清单

> 来源：2026-10-16 提额审批台"永远加载中"事件的完整复盘。
> 用途：改代码后出问题时照此排查；写代码前照此避坑。两个项目（主项目/子服务）通用。

---

## 一、排查方法论：从最后一次改动往上扒（改动回溯法）

**适用场景**：改了代码之后出现新问题，或者老问题以为修好了但没解决。

**核心口诀**：
- **新问题 = 先查新改动**，不要先怀疑环境、重启、缓存等外部因素。
- **老问题没解决 = 先查"改动是否真的生效"**：进程重启了没有？数据写进去了没有？浏览器/服务端缓存刷了没有？

**五步流程**：

1. **锁定时间线**：问题出现前，最后一次代码改动动了哪几处（精确到文件+行）。改动记录、对话记录、文件修改时间都算证据。
2. **只审这些 diff**：把嫌疑集中在自己的改动上，逐处过一遍，不要漫无目的地全局搜索。本次教训：曾连续两次误判为"重启空窗""旧令牌 403"，真凶是自己的编辑——**先怀疑自己，成本最低**。
3. **顺着数据流扒**：从改动点向上/向下追——
   - 这段代码写在什么**宿主**里？（纯 .py？嵌在字符串模板里？嵌在 HTML 里？）
   - 它的输出被谁**消费**？中间经过什么**转换**？（转义、编码、宏替换、模板拼接）
   - 宿主对内容有没有**二次处理**？（Python 的 `"""` 字符串会吃掉 `\n`！）
4. **三层验证代替猜测**（每层都拿证据，不靠"应该好了"）：
   - 语法层：`py_compile` / 把页面实际下发的 JS 抽出来跑 `node --check`
   - 数据层：台账 JSON / 日志 / 数据文件里**亲眼确认**数据写进去了
   - 端到端层：真实浏览器打开页面看渲染、真实请求走一遍业务流
5. **一次只验证一个假设**，被证据推翻就立刻换假设，不要在同一个猜测上反复加码。

## 二、案例复盘：审批台"永远加载中"（2026-10-16）

| 环节 | 内容 |
|---|---|
| 现象 | 1911 审批台永远卡在"加载中…"，但 PowerShell 直连 `/api/list` 返回 200，页面 HTML 也能显示 |
| 误判① | "打开页面时服务在重启空窗"——错：15 秒自动刷新早就该自愈 |
| 误判② | "旧令牌 403 导致静默失败"——错：`/api/list` 根本不校验令牌 |
| 真凶 | 审批台页面是嵌在 Python `"""` 字符串里的 JS。新增的 `esc(x.purpose).replace(/\n/g, '<br>')` 中，`\n` 被 **Python 提前转义成真实换行**，浏览器收到"正则里含裸换行"→ 整个 `<script>` 语法错误 → **load() 从未执行**，页面永远停在初始"加载中" |
| 定位 | 按改动回溯法逐处审自己的 diff（用户提示"从你改的代码往上扒"，一击命中） |
| 修复 | Python 源码里写 `\\n`（转义后浏览器收到 `/\n/g`）；并把**服务实际下发的页面 JS** 抽出来 `node --check` 验证通过 |
| 次生发现 | ① 外部工具链启动的服务进程会随命令结束被清掉——要用 WMI 独立拉起；② 旧台账记录没有新字段 `purpose`，展示端必须容错 |

**经验提炼**：
- "API 正常 + 页面白死" = 九成是**前端脚本解析/运行时错误**，先开浏览器控制台看红字，或把 JS 抽出来做语法检查。
- 页面卡在初始占位文案（如"加载中…"）= 脚本**根本没执行**，不是接口慢。
- 嵌在字符串里的代码，转义是第一嫌疑。

## 三、本项目开发防坑清单（写代码前过一遍）

1. **Python 内嵌 JS/HTML（如 ADMIN_PAGE_HTML、邮件 HTML 模板）**
   - 反斜杠一律双写：`\\n`、`\\d`、`\\/`；`{}` 在 f-string 里还要翻倍。
   - 能拆成独立 `.js` 文件的，不要内嵌；内嵌是转义事故高发区。
   - 改动后必做：`py_compile` + 抽取实际下发内容做 `node --check`（临时文件放 Temp，验完删）。

2. **页面改动必须真实浏览器验证**：curl 到 HTML ≠ 渲染正常。脚本语法错误、白屏、占位符卡死都只有浏览器能暴露。

3. **服务重启语义**
   - Python 不热加载：改完必须重启服务。
   - 每次重启，1911 审批台令牌重新生成 → 页面要 F5（现在弹窗会明确提示"令牌不符，请刷新页面"）。
   - `启动控制台.bat` 的窗口就是服务器本体，**关窗 = 停服**。外部工具（AI/脚本）拉起服务要用 WMI（`Win32_Process.Create`），普通子进程会随工具会话结束被连带杀掉。

4. **新增字段走全链路**：表单 → 接口 → 台账 JSON 落盘 → 展示。每一环都要验证：
   - 后端入库用 `.strip()`/限长归一化（纯空白视为未填）；
   - 展示端对**旧数据缺字段**容错（`x.purpose ? ... : ''`、后端 `.get()` 兜底）；
   - 在数据文件里亲眼看到新字段，才算功能完成。

5. **测试数据与真实数据分清**：修 bug 前产生的旧记录，不会自动拥有新字段；验证新功能必须产生一条新数据，别对着旧记录找新效果。

6. **结论只用证据说话**：区分"已验证事实"（附日志/数据/截图）与"推测"。连续两次推翻自己的猜测时，回到第 1 步重新锁时间线。

## 四、给 AI 协作的补充约定

- 修完先**自证三连**：编译/语法 → 数据落盘 → 端到端浏览器（或真实请求）。
- 修改前先想清楚这段代码的"宿主"和"消费者"，内嵌模板先查转义。
- 排查时把已排除的假设和证据记下来，避免绕圈重复同一假设。
- 用户提示"看看你刚改的代码"时，优先执行改动回溯法——实践证明比全局搜索快得多。

## 五、经验库（持续追加；每条独立可测，用得上留、用不上删）

### A. 排查定位

1. 【进程跑的是新代码还是旧代码】进程 StartTime 与被改文件的 mtime 对照，一秒定性"改了没生效"类问题（案例：进程 19:20:30 启动 vs 代码 19:28:08 改完 → 必是旧代码）。
2. 【服务死没死】`Get-NetTCPConnection` 查端口监听与归属 pid。"connection refused" ≠ 代码错，先确认进程在不在。
3. 【用日志还原用户操作】usage.jsonl / 台账按时间线一拉：用户点没点、后端收没收到、状态码是多少（200/400/409）一目了然。本次靠它证明"19:35 后没有任何新申请"，直接排除"后端没存"。
4. 【对照实验切分故障域】PowerShell 直连 API 正常 + 浏览器异常 → 问题在浏览器执行侧（脚本错误/缓存/协议），不在后端。
5. 【页面卡在初始占位符】（如"加载中…"）= 脚本根本没执行（解析错误），不是接口慢；浏览器控制台看红字最快。
6. 【新数据没进台账】先过业务校验链：防重复（409）、参数范围（400）、验证码——可能是规则拦截，不是 bug。
7. 【一次只验一个假设】假设被证据推翻就立刻换，不在同一猜测上反复加码；连续两次翻车 → 回到时间线重新锁定。

### B. 环境 / 进程

8. 【Python 不热加载】改完必须重启服务；排查前先做第 1 条的时间对照。
9. 【外部工具拉起服务要用 WMI】（`Win32_Process.Create`）：普通子进程会随工具会话结束被连带清掉；WMI 进程父级是系统服务，独立存活。
10. 【bat 窗口 = 服务器本体】关窗即停服，运行日志就在窗口里。
11. 【bat 文件必须 GBK + CRLF】否则中文乱码、命令被截断（启动脚本曾中招）。
12. 【PowerShell 子进程丢 Cert: 盘】宿主泄漏 PS7 的 PSModulePath 时，spawn powershell 5.1 前须重置该变量。
13. 【TLS 监听必须 settimeout】否则一条半开连接卡死整个 accept 循环（握手内联在循环里）。
14. 【自签证书】Python ssl 只认 PEM；用 pwsh/.NET 生成 PEM 对，别拿 PFX 硬喂 load_cert_chain。

### C. 编码 / 转义 / 模板

15. 【内嵌模板转义第一嫌疑】Python `"""` 里写 JS：`\n` 会变真实换行、反斜杠一律双写；能拆独立 .js 就别内嵌。
16. 【5 位以上 Unicode 码位必须 `\UXXXXXXXX`】`\u` 只吃 4 位十六进制，多余字符会与后面的字符组成意外范围（P0 案例：`\u1bca0` 吞掉全部 ASCII 数字英文）。
17. 【回归用例必须覆盖边界】修"剥离隐形字符"要同时验证 ASCII/数字/URL 不被误伤——只测目标场景会漏掉误伤（P0 教训）。

### D. 前后端联调

18. 【页面改动必须真实浏览器验证】curl 到 HTML ≠ 渲染正常；语法错误、白屏、占位符卡死只有浏览器能暴露。
19. 【重启后内部页面要 F5】1911 令牌每次启动重新生成；审批失败弹窗现在会显示"令牌不符，请刷新页面"，不再无声。
20. 【静态资源与已打开页面】服务端已发 no-cache，但浏览器里已打开的页面仍是旧脚本——强刷 Ctrl+F5 保平安。
21. 【keep-alive 竞态】服务端空闲保持 300s + 前端 GET 失败自动重试一次，根治浏览器 ERR_ABORTED。
22. 【前后端同源反代】8080 托管静态并反代 1314：无跨域、无混合内容；1314 直连保留给外部程序。

### E. 数据与安全

23. 【防御式取值】外部输入/子进程输出用 `.get()` + returncode 校验，别让 `or "{}"` 把空输出兜成成功（P1 教训：偶发 KeyError 500）。
24. 【SSRF 连接钉定】"校验时解析一次、连接时再解析一次" = TOCTOU 洞；校验和连接必须用同一个解析结果（I1 修复方案，勿从零重写）。
25. 【数据文件原子写】tmp + `os.replace`；跨进程共享的 JSON 用 mtime 热重载 + 锁。
26. 【归一化下沉到存储层】strip/限长放在 add() 这类统一入口，HTTP/CLI/测试任何来源自动一致（purpose 先放端点、后下沉的教训）。
27. 【文案唯一来源】CLI 与 1911 审批台共用 `conc_decide_and_notify`，邮件文案只写一处，防两处漂移。
28. 【敏感信息脱敏贯穿】key_mask / mask_email 在日志与页面统一使用；自由文本（备注/目的）入 HTML 前必须 esc_html。

### F. 协作 / 工作流

29. 【口述需求先复述确认】语音输入的需求，动手前用一两句复述要点对齐，再写码。
30. 【小步快走】一次只改一个主题，改完立即验证再继续；攒一把改动，出了问题难定位。
31. 【测试脚本放 Temp、用完删】项目目录只留交付物，不留调试残渣。
32. 【文档与代码同步】bug 修复进 BUGS.md（定位/结论/状态三要素），方法论进本文件；给"另一个项目的 AI"写文档时留足上下文（确切文件:行号）。
33. 【dev 模式自测邮件】Mailer 无授权码 = dev 模式只打印不真发，全链路可测不触网、不耗配额。
34. 【汇报区分事实与推测】"已验证"附证据（日志/数据/截图）；"怀疑"明确标注未验证。
