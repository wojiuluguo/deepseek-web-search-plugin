# 双方融合经验库（主项目 × 子服务 提纯版）

> 来源：[01-主项目经验](../01-主项目经验/)（问题清单 ×2 + 对话沉淀）+ [02-子项目经验](../02-子项目经验/)（34 条）去重、合并、提纯。
> 每条标注归属：**【主】**=主项目独有 / **【子】**=子服务独有 / **【合】**=两边同源或融合强化。
> 冲突时以实测证据为准。本库是三库中唯一**可修订**的；01/02 原文只增不删。

## 一、排查方法论

1. 【子】【合】**改动回溯法**：出问题先从最后一次改动往上扒，不全局搜索。进程 StartTime vs 被改文件 mtime 一秒定性"改了没生效"。
2. 【主】【合】**四步法定性**：判定 → 理由 → 反问 → 确认；**100% 确认才是 bug**，否则搁置留证（不确定原因 + 观察计划）。非 bug 嫌疑也要实验定性，不凭感觉驳回。
3. 【子】【合】**一次只验一个假设**：被证据推翻立刻换；连续两次翻车 → 回到时间线重新锁定。
4. 【子】【合】**对照实验切分故障域**：A 通路正常 + B 通路异常 → 问题在 B 侧执行层，不在共享层（PowerShell 直连 API 正常 + 浏览器异常 → 查前端脚本）。
5. 【主】【子】【合】**结论只用证据说话**：汇报区分"已验证事实"（附日志/数据/截图）与"推测"。
6. 【主】【合】**分段计时定位挂死**：给长链路每步打 `[stage] 开始/结束` 日志，stderr 最后一条就是挂点——比猜"哪一步无界等待"快一个量级（采集链挂死根治全靠它）。
7. 【主】【合】**死代码指控先查活调用方**：grep 全仓调用点再定性，同一流程可能得出"确删"或"驳回"两种结论。
8. 【主】【合】**日志还原用户操作**：台账/usage 按时间线一拉，用户点没点、后端收没收、状态码多少一目了然。

## 二、写码铁律

9. 【主】【子】【合】**防御式取值**：外部输入/子进程输出用 `.get()` + returncode 校验；警惕 `or "{}"` 把空输出兜成成功（P1 同源教训：偶发 KeyError 500）。
10. 【主】【子】【合】**5 位以上 Unicode 码位一律 `\UXXXXXXXX`**（P0：`\u` 只吃 4 位十六进制，`\u1bca0` 曾吞掉全部 ASCII）。
11. 【主】【子】【合】**字符剥离类功能的回归必须验证边界**：修"剥离隐形字符"要同时断言 ASCII/数字/URL/VS16 不被误伤——只测目标场景会漏掉误伤。
12. 【主】【合】**Playwright 三件套**：①无 timeout 参数的 evaluate 全部有界化（`_eval_bounded`）；②`browser.close()` 对长连页面（WebSocket/SSE）无限阻塞 → 主线程三级有界关闭 page→context→browser；③sync API 线程绑定，跨线程调用直接 greenlet 报错（线程方案死路）。
13. 【主】【合】**隐式等待黑洞**：逐个试 selector，元素不存在时每个等 30s，全 miss 就是 30s×N——改单次 JS 求值一次往返（番茄 330s/章 → ~4s/章）。
14. 【主】【子】【合】**子进程调用必须 try/except + 超时**；全局看门狗 `--timeout N` 防"各步有界但总和无界"的挂死（网易云/番茄两例实锤）。
15. 【主】【合】**宿主保护靠子进程隔离**：长任务嵌套调用（下载电路里的搜索步）走子进程，下游 driver 突死不拖死宿主——driver 死后进程内任何 Playwright 调用都可能永久挂起，进程内重启是死路。
16. 【主】【合】**Windows 路径 260 上限**：yt-dlp outtmpl 截断 + `trim_file_name` 硬限；ffmpeg 子进程必带 `encoding="utf-8", errors="ignore"`（中文路径）。
17. 【子】【合】**内嵌 JS/HTML 模板**：Python `"""` 里写 JS 反斜杠一律双写、f-string `{}` 翻倍；能拆独立 .js 文件就别内嵌；改完 `py_compile` + 抽取实际下发内容 `node --check`。
18. 【主】【合】**同名函数跨文件签名必须一致**：参数顺序相反是复制调用地雷（search/search_browser 曾相反，调用碰巧没踩）。
19. 【主】【合】**宁可 import 归一，不留兜底复制品**：基建副本漂移（当天的修复漏改副本）发生过不止一次——副本漂移温床 = 逐出口接线/复制粘贴兜底。
20. 【子】【合】**归一化下沉到统一入口**（add()/存储层），HTTP/CLI/测试任何来源自动一致；新字段走全链路逐环验证，旧数据缺字段要容错。
21. 【子】【合】**页面改动必须真实浏览器验证**：curl 到 HTML ≠ 渲染正常；白屏/占位符卡死 = 脚本解析错误，浏览器控制台看红字最快。
22. 【子】【合】**Python 不热加载**：改完必须重启服务；排查前先做 StartTime/mtime 对照。外部工具拉起服务用 WMI（`Win32_Process.Create`），普通子进程随工具会话被连带杀。bat 必须 GBK+CRLF。
23. 【子】【合】**TLS 监听必须 settimeout**：否则一条半开连接卡死整个 accept 循环。
24. 【主】【合】**测试数据与真实数据分清**：修 bug 前的旧记录不会自动拥有新字段；验证新功能必须产生新数据。
25. 【子】【合】**数据文件原子写**：tmp + `os.replace`；跨进程共享 JSON 用 mtime 热重载 + 锁。

## 三、安全红线

26. 【主】【合】**破坏性操作必须有目录边界护栏**：删除类操作（`--clean/--assemble`）要求目标在项目专用树内，越界 exit 2 明确拒绝——"看起来是垃圾"的判定规则（图片<150KB）落到真实目录就是误删。
27. 【主】【合】**URL scheme 白名单双层设防**：urllib 层 + Playwright 兜底层都挡——`except` 吞掉第一层拒绝转浏览器重试，`goto file://` 照样读本地文件；一层等于没防。
28. 【子】【合】**SSRF 连接钉定**："校验时解析一次、连接时再解析一次" = TOCTOU 洞；校验和连接必须用同一个解析结果。服务端化时直接用现成实现，勿从零重写。
29. 【主】【合】**隐形字符在聚合源头净化**：零宽/双向符/Unicode Tag 块（ASCII Smuggling 载体）从网页进结果再进 AI prompt——在聚合点（dispatch/入库前）接线，下游全部自动干净；逐出口接线是副本漂移温床。
30. 【子】【合】**敏感信息脱敏贯穿**：key_mask / mask_email 在日志与页面统一使用；自由文本入 HTML 前 esc_html。
31. 【主】【合】**红线必须机制化**：`search-api-service/` 不入库不进 zip——.gitignore 挡 + 发版前 `git ls-files` 复核为 0；只写文档不落实机制不算防住。

## 四、协作与流程

32. 【子】【合】**口述需求先复述确认**：语音输入的需求，动手前用一两句复述要点对齐；"检查/审核"≠"修改"，用户未明确说改就不改。
33. 【主】【子】【合】**小步快走**：一次只改一个主题，改完立即验证再继续；攒一把改动出了问题难定位。
34. 【主】【子】【合】**自证三连**：编译/语法 → 数据落盘 → 端到端（浏览器或真实请求）；修完才算完。
35. 【子】【合】**测试脚本放 Temp 用完删**：项目目录只留交付物，不留调试残渣。
36. 【主】【子】【合】**bug 走台账、方法论进 skill**：台账三要素（定位 文件:行 / 复核结论 / 状态）；给另一个项目的 AI 写文档要留足上下文（确切文件:行号）。
37. 【主】【合】**双语文档对称**：英文是默认视图，详细内容必须与中文对等，不能只有中文；更新记录独立成 CHANGELOG（时间轴 + 分月索引 + 详细记录），README 只留最近 3 版。
38. 【主】【合】**累积发版 + 规范打包**：修复 ≠ 发版，用户明确指示才统一发；Release Notes 双语每版重写、有用内容置顶；`git archive` 打包（天然继承 .gitignore），打包前 `git ls-files` 审清单；版本号四处同步（SKILL/package.json/双语 README/CHANGELOG）。
39. 【主】【子】【合】**只增不删**：过时条目标注弃用 + 原因，保留演化轨迹；经验每条独立可测，用得上留、用不上标弃用。

## 五、工作方法（2026-10-16 自主项目工作习惯蒸馏补充）

40. 【主】【合】**构造性复现先于修复**：修前先写出稳定触发 bug 的最小场景，修完跑同一场景确认消除——修复的起点和终点都是复现，不是"看起来改好了"。
41. 【主】【合】**兼容面盘点**：改共享件语义后逐个列出全部消费方核清影响，允许合入的前提是"变化的影响面被完整说清"。
42. 【主】【合】**一个入口出缺口，查所有兄弟入口**：`--hosts` 绕私网实锤后连带查出 file:// 走 Playwright 兜底绕过第一层白名单——同类问题不会只存在于被举报的那一处。
43. 【主】【合】**操作类红线逐条落机制**：git add 按名单逐个加（不用 -A）、推完 `git ls-files` 复核、zip 打完肉眼过条目——每一步都有"亲眼确认"动作，不信"命令没报错就是对了"。
